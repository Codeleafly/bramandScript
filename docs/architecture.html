Chapter 14

Modules & Centralized Package Architecture

BramandScript implements a clean Deno-style module architecture. Modules are loaded via direct filesystem path or remote URL with deduplication and aliased namespace encapsulation.

Module Syntax Modes

bramand — math_utils.bmd (module file) 
const PI = 3.1415926535

fn hypot(a, b) {
    return ((a ** 2) + (b ** 2)) ** 0.5
}
bramand — main.bmd 
// 1. Direct namespace import (exports grouped into 'math' hash object)
import "./math_utils.bmd" as math
print("PI =", math.PI)
print("Hypot(3, 4) =", math.hypot(3, 4))

// 2. Global scope import (exports injected directly into current scope)
import "./math_utils.bmd"
print("Direct hypot:", hypot(5, 12))

Centralized Package Cache ($HOME/.bramand_libs/)

Remote and package modules are stored in a centralized cache directory at $HOME/.bramand_libs/<package>@<version>/. This eliminates bloat, preventing repeated downloads across distinct project roots.

Package Manager CLI (bramand pkg)

Manage, install, and list packages globally in your environment using the unified CLI tool:

bash — Package Manager Commands 
# List all installed global packages
bramand pkg list

# Install a package from local directory or file
bramand pkg install ./my_pkg math@1.0.0

# Remove package
bramand pkg remove math@1.0.0

# Scaffold new library package with index.bmd
bramand pkg init logger@0.1.0
Chapter 16

Intelligent Diagnostic Engine (Rust/Clang-Style with Context Window)

BramandScript features a world-class diagnostics engine inspired by Rust and modern Clang. When an error occurs (syntax error, compile-time symbol resolution failure, or runtime error), the diagnostics engine renders:

  • 10 Lines of Code Context: 5 context lines above and 5 context lines below the incident line.
  • Dynamic Caret Pointer: Precise column caret (^~~~) highlighting the exact offensive token.
  • Zero Box Borders: High-readability minimalist gutters without noisy borders.
  • Intelligent Hints: Actionable suggestions analyzing the identifier name or error condition.

Sample Diagnostic Output

terminal — diagnostic report 
error[CompileError]: undefined variable 'userScore'
  --> test.bmd:8:11
     |
   3 | let baseBonus = 50
   4 | fn calculateRank(points) {
   5 |     let multiplier = 2
   6 |     return points * multiplier
   7 | }
   8 | let final = userScore + baseBonus
     |            ^~~~~~~~~ [Hint: Declare variable using 'let userScore = ...' or check spelling]
   9 | print("Final:", final)
  10 | print("Done")
     |
Chapter 17

Virtual Machine & Architecture (Lexer -> Pratt Parser -> Bytecode -> Stack VM)

BramandScript does NOT use slow tree-walk evaluation. Every source file travels through a four-stage Bytecode VM pipeline:

architecture pipeline 
Source Code (.bmd)
       │
       ▼
 1. Lexer (tokenizes into typed Token structs with Line & Col tracking)
       │
       ▼
 2. Pratt Parser (Top-down operator precedence Abstract Syntax Tree)
       │
       ▼
 3. Bytecode Compiler (Symbol Scoping, Constants Pool, Emits Opcodes)
       │
       ▼
 4. Virtual Machine (Stack loop, 2048 stack cells, Frame call-stack)

Instruction Set & Opcode Reference

Instructions are encoded as 1-byte opcodes followed by optional 1-byte or 2-byte BigEndian operands.

Opcode Operands Stack Effect Description
OpConstant [uint16] index --> [val] Loads constant from constant table and pushes to stack
OpPop none [val] --> Pops top element off stack
OpAdd, OpSub, OpMul, OpDiv, OpMod, OpPow none [a, b] --> [result] Binary arithmetic operations on integers or floats
OpEqual, OpNotEqual, OpGreaterThan, OpGreaterThanEqual none [a, b] --> [bool] Comparison operations pushing canonical True or False
OpJump [uint16] offset none Unconditional jump setting instruction pointer
OpJumpNotTruthy [uint16] offset [cond] --> Pops condition; jumps if falsy (false or null)
OpSetGlobal / OpGetGlobal [uint16] globalIndex [v] --> / --> [v] Sets or retrieves variable from 65,536 globals table
OpSetLocal / OpGetLocal [uint8] localIndex [v] --> / --> [v] Sets or retrieves variable offset from frame base pointer
OpClosure [uint16] const, [uint8] free [free...] --> [closure] Creates closure wrapping compiled fn and free cells
OpCall [uint8] numArgs [fn, args...] --> [frame] Allocates new Frame on call stack, transfers execution
OpReturnValue / OpReturn none [frame] --> [returnVal] Restores caller frame and pushes return value
VM Introspection & Hotspots

Bytecode Disassembler & Execution Profiler

BramandScript provides production-grade bytecode introspection and profiling primitives directly within the CLI and interactive REPL. Developers can disassemble compiled functions into assembly instructions and profile opcode execution hotspots with zero external tools.

1. Interactive Bytecode Disassembler (:disasm)

The disassembler traverses raw bytecode byte streams, decodes opcodes using the opcode definitions table, resolves big-endian operands, and annotates constants and symbols:

CLI & REPL Disassembly 
# CLI command
bramand disasm program.bmd

# Interactive REPL command
:disasm let x = 40 + 2

2. Runtime Execution Profiler (:profile)

When profiling is active, the Virtual Machine measures per-instruction execution duration with high-resolution CPU clocks into a fixed [256] duration array. After execution, it outputs a formatted hotspot analysis table displaying opcode counts, total execution time, average latency per operation, and relative percentage:

Chapter 18

Contributing & Community Guide

BramandScript welcomes contributions from software architects, compiler enthusiasts, and open source developers worldwide.

Contribution Mandates

  • Standard Library Exclusivity: Never introduce third-party Go modules or run go get.
  • Comprehensive Unit Tests: Every new feature must include automated test coverage in its corresponding package test file (*_test.go).
  • No Emojis Rule: Uphold clean Unicode typography across documentation, code, CLI, and error handlers.
  • Track Roadmap with bmd-task: Run node tools/task.js list to inspect active weekly tasks.
Run Full Test Suite

Verify all subsystems locally before submitting pull requests: 

go test ./... -v
