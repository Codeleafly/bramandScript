Chapter 1

Introduction, Vision & Zero-Dependency Pure Go Philosophy

BramandScript (from the Sanskrit Brahmand, meaning "Universe" or "Cosmos") is an independent, general-purpose programming language created to provide complete execution sovereignty. It is engineered from scratch in Go's standard library (stdlib) without relying on a single external package or third-party runtime.

Architectural Principle: Zero Dependencies

The entire pipeline—from Unicode scanner, Pratt parser, and bytecode compiler, to the register-free stack virtual machine, memory globals, symbol table, and terminal REPL—builds completely offline with go build. It guarantees 100% deterministic compilation across Termux (Android ARM64), Linux, macOS, and Windows.

Core Pillars

  • Clean, International English Syntax: Familiar to developers from Python, JavaScript, and Go, with no syntactic noise or forced ceremony.
  • Bytecode Virtual Machine: Every source program is compiled to dense, BigEndian binary instructions executed by a high-throughput stack loop.
  • Zero Emojis Standard: Clean, professional developer diagnostics utilizing Unicode geometric symbols (✦, ❯, ·) and standard bracketed status badges ([OK], [INFO], [ERROR]).
  • First-Class Termux & ARM64 Support: Developed directly on Android mobile workstations with native performance.
Chapter 2

Quickstart, Installation & Global CLI (bramand / bmd)

BramandScript provides a unified native binary executable with aliases bramand and bmd. Pre-compiled standalone releases are automatically published for Android (Termux), Linux, macOS (Apple Silicon & Intel), and Windows via GitHub Actions.

1. Smart Universal Installer (Linux, macOS, Android Termux)

Run the smart installer one-liner. It auto-detects your OS (Linux, Darwin, Android Termux) and CPU architecture (amd64, arm64, armv7), pulls the latest release binary, and configures global symlinks:

bash — terminal 
curl -fsSL https://raw.githubusercontent.com/Codeleafly/bramandScript/master/install.sh | bash

2. Windows PowerShell Installer

On Windows, open PowerShell and run:

powershell 
irm https://raw.githubusercontent.com/Codeleafly/bramandScript/master/install.ps1 | iex

3. Manual Compilation with Local Go Toolchain

If you have the Go toolchain installed, clone the repository and compile directly without external dependencies:

bash — compilation 
git clone https://github.com/Codeleafly/bramandScript.git
cd bramandScript
go build -ldflags="-s -w" -o bramand main.go

# Install to system PATH
cp bramand "${PREFIX:-/usr/local}/bin/bramand"
ln -sf "${PREFIX:-/usr/local}/bin/bramand" "${PREFIX:-/usr/local}/bin/bmd"

Syntax, Semicolon-Optional Model & Comments

BramandScript features a modern, semicolon-optional grammar. Semicolons (;) may be used to separate statements on the same line, but are never required at line endings.

bramand — syntax and comments 
// Single-line comments start with double slashes

/*
   Multi-line comments can span
   across multiple lines cleanly.
*/

// Clean, semicolon-free statements
let title = "BramandScript"
let version = 0.1

// Semicolons can be used for multi-statement single lines:
let a = 1; let b = 2; let c = a + b
print(c)
Chapter 5

Variables (let), Constants (const), and Scoping

Identifiers are declared using let (for mutable bindings) or const (for immutable bindings). Variables are lexically scoped.

bramand — variables and constants 
// Mutable variable
let score = 100
score = 150        // Direct reassignment
score += 25        // Compound addition (score is now 175)
score -= 10        // Compound subtraction
score *= 2         // Compound multiplication
score /= 4         // Compound division

// Immutable constant
const MAX_CONNECTIONS = 1024

// Trying to reassign a const raises a CompileError:
// MAX_CONNECTIONS = 2048 // error[CompileError]: cannot reassign to constant variable 'MAX_CONNECTIONS'
Lexical Scoping Rules

Top-level variables reside in the GlobalScope (indexed up to 65,536 globals). Variables declared inside functions belong to the LocalScope mapped to the VM frame's base pointer. Variables referenced from an enclosing function outer scope are converted into FreeScope closure cells!

Chapter 8

Control Flow (if / else if / else with optional parens, while)

Conditionals in BramandScript do not require enclosing parentheses around their condition expressions, keeping syntax clean and readable.

if, else if, else

bramand — conditionals 
let speed = 75

// Clean syntax without parentheses:
if speed > 100 {
    print("Extreme Velocity!")
} else if speed >= 60 {
    print("Cruising Speed")
} else {
    print("Idle or Slow")
}

// If expressions produce values:
let category = if speed >= 60 { "Fast" } else { "Slow" }

while Loops with break and continue

Loops execute while their condition evaluates to a truthy value. Control jumps are backpatched directly in the bytecode instruction stream using OpJumpNotTruthy and OpJump.

bramand — while loops 
let count = 0
let total = 0

while count < 10 {
    count += 1

    if count == 3 {
        continue // Skip adding 3
    }

    if count == 8 {
        break    // Terminate loop early
    }

    total += count
}

print("Computed Total:", total)
Chapter 9

Functions & Mutable Lexical Closures (fn)

Functions in BramandScript are first-class citizens. They can be defined as named functions or assigned as anonymous expressions. Crucially, closures capture free variables by reference, enabling mutable state encapsulation!

bramand — functions and closures 
// Named function declaration
fn multiply(a, b) {
    return a * b
}

// Higher-order function returning a stateful closure
fn createCounter(start) {
    let count = start
    return fn() {
        count += 1     // Mutates free variable in outer lexical scope!
        return count
    }
}

let counterA = createCounter(10)
print(counterA()) // 11
print(counterA()) // 12

let counterB = createCounter(100)
print(counterB()) // 101
print(counterA()) // 13 (independent state!)
Under the Hood: Opcodes for Closures

When a function references identifiers from an enclosing scope, the compiler emits OpClosure <constIndex> <numFree>. Free variables are pushed to the stack and captured into an array of object references inside the closure object. Access and mutation are performed via OpGetFree and OpSetFree.

Arrays, Hashes & Index Expressions (arr[i] = v, hash[k] = v, obj.prop, .length)

Hashes support any hashable key (Integers, Strings, Booleans). String keys can be accessed and assigned using either bracket syntax hash["key"] or ergonomic dot syntax hash.key!

Chapter 11

Iterators & for-in Loops (Arrays, Strings, Hashes, with break & continue)

BramandScript provides built-in for-in loops. The loop syntax optionally accepts an index variable before the item identifier.

bramand — for-in loops 
let languages = ["Go", "BramandScript", "Rust", "Zig"]

// 1. Item-only iteration
for lang in languages {
    print("Lang:", lang)
}

// 2. Index + Item iteration
for idx, lang in languages {
    print("[" + str(idx) + "]", lang)
}

// 3. Iterating over strings (character by character)
for char in "Bramand" {
    print("char:", char)
}

// 4. Early termination with break & continue
for i, val in [10, 20, 30, 40, 50] {
    if val == 20 { continue }
    if val == 40 { break }
    print("Yielded:", val)
}
Chapter 12

Structs & OOP Methods (struct Point { x, y, fn dist() { ... } })

BramandScript introduces clean object-oriented structs. A struct compiles into an instantiator closure that constructs a typed hash instance possessing the declared fields and bound methods.

bramand — structs and methods 
// Define a 2D Point struct with methods
struct Point {
    x, y

    fn distanceSquared(otherX, otherY) {
        let dx = x - otherX
        let dy = y - otherY
        return (dx ** 2) + (dy ** 2)
    }

    fn translate(offsetX, offsetY) {
        x += offsetX
        y += offsetY
    }
}

// Instantiation
let pt = Point(10, 20)

// Field access
print("Initial coordinates:", pt.x, pt.y)

// Method invocation
print("Dist to (0,0):", pt.distanceSquared(0, 0))

// Mutation via method or direct dot access
pt.translate(5, -10)
pt.x = 100
print("After translation:", pt.x, pt.y)

Pattern Matching (match subject { case ... => { ... }, default => { ... } })

BramandScript features first-class pattern matching. Matching expressions return values, support multiple values per case separated by commas, and provide a fallback default arm.

let statusCode = 404

let responseMessage = match statusCode {

Lightweight Tasks with spawn

BramandScript provides native concurrency via the spawn keyword. Calling a function or closure with spawn dispatches execution into a lightweight Go goroutine with an isolated stack, safe argument passing, and independent call frames, all sharing a thread-safe globals store.

bramand — Concurrency with spawn

// Spawn named function

// Spawn anonymous closure

    println("Anonymous task completed")
}()
Message Passing

Channels & Synchronized Communication

Channels allow concurrent tasks to communicate safely and synchronize execution without explicit locking. Created using the chan([capacity]) builtin, channels support unbuffered and buffered message queues.

bramand — Channel send & receive 
// 1. Unbuffered rendezvous channel
let ch = chan()

spawn fn() {
    ch <- 42 // Send value into channel
}()

let result = <-ch // Blocks until received
println("Received:", result)

// 2. Buffered channel & close()
let queue = chan(2)
queue <- "Alpha"
queue <- "Beta"
close(queue)

println(<-queue) // "Alpha"
println(<-queue) // "Beta"

Mutexes & WaitGroups

For shared mutable state, BramandScript includes native mutex() locks and wait_group() coordination barriers.

let m = mutex()
let wg = wait_group()

let counter = 0
wg.add(2)

spawn fn() {
    m.lock()
    counter += 1
    m.unlock()
    wg.done()

    m.unlock()
    wg.done()

Realtime

RFC 6455 WebSockets (Zero-Dependency)

A complete, compliant implementation of the RFC 6455 WebSocket protocol built entirely with the Go Standard Library. Includes automatic client-side frame masking, server-side unmasking, ping/pong heartbeats, and binary/text frame streams.

bramand — Realtime WebSocket Communication 
// Start WebSocket Server
let wsSrv = ws_server("127.0.0.1:8081", "/ws")
spawn fn() {
    let conn = wsSrv.accept()
    while conn.is_open {
        let msg = conn.recv()
        if msg == null { break }
        conn.send("Server Ack: " + msg)
    }
}()

// Connect WebSocket Client
let ws = ws_connect("ws://127.0.0.1:8081/ws")
ws.send("Hello Bramand WebSocket!")
let reply = ws.recv()
println("Received:", reply)
ws.close()
wsSrv.close()

Modules & Centralized Package Architecture

BramandScript implements a clean Deno-style module architecture. Modules are loaded via direct filesystem path or remote URL with deduplication and aliased namespace encapsulation.

Module Syntax Modes

bramand — math_utils.bmd (module file) 
const PI = 3.1415926535

fn hypot(a, b) {
    return ((a ** 2) + (b ** 2)) ** 0.5
}
bramand — main.bmd 
// 1. Direct namespace import (exports grouped into 'math' hash object)
import "./math_utils.bmd" as math
print("PI =", math.PI)
print("Hypot(3, 4) =", math.hypot(3, 4))

// 2. Global scope import (exports injected directly into current scope)
import "./math_utils.bmd"
print("Direct hypot:", hypot(5, 12))

Centralized Package Cache ($HOME/.bramand_libs/)

Remote and package modules are stored in a centralized cache directory at $HOME/.bramand_libs/<package>@<version>/. This eliminates bloat, preventing repeated downloads across distinct project roots.

Package Manager CLI (bramand pkg)

Manage, install, and list packages globally in your environment using the unified CLI tool:

bash — Package Manager Commands 
# List all installed global packages
bramand pkg list

# Install a package from local directory or file
bramand pkg install ./my_pkg math@1.0.0

# Remove package
bramand pkg remove math@1.0.0

# Scaffold new library package with index.bmd
bramand pkg init logger@0.1.0

Virtual Machine & Architecture (Lexer -> Pratt Parser -> Bytecode -> Stack VM)

BramandScript does NOT use slow tree-walk evaluation. Every source file travels through a four-stage Bytecode VM pipeline:

architecture pipeline 
Source Code (.bmd)
       │
       ▼
 1. Lexer (tokenizes into typed Token structs with Line & Col tracking)
       │
       ▼
 2. Pratt Parser (Top-down operator precedence Abstract Syntax Tree)
       │
       ▼
 3. Bytecode Compiler (Symbol Scoping, Constants Pool, Emits Opcodes)
       │
       ▼
 4. Virtual Machine (Stack loop, 2048 stack cells, Frame call-stack)

Instruction Set & Opcode Reference

Instructions are encoded as 1-byte opcodes followed by optional 1-byte or 2-byte BigEndian operands.

Opcode Operands Stack Effect Description
OpConstant [uint16] index --> [val] Loads constant from constant table and pushes to stack
OpPop none [val] --> Pops top element off stack
OpAdd, OpSub, OpMul, OpDiv, OpMod, OpPow none [a, b] --> [result] Binary arithmetic operations on integers or floats
OpEqual, OpNotEqual, OpGreaterThan, OpGreaterThanEqual none [a, b] --> [bool] Comparison operations pushing canonical True or False
OpJump [uint16] offset none Unconditional jump setting instruction pointer
OpJumpNotTruthy [uint16] offset [cond] --> Pops condition; jumps if falsy (false or null)
OpSetGlobal / OpGetGlobal [uint16] globalIndex [v] --> / --> [v] Sets or retrieves variable from 65,536 globals table
OpSetLocal / OpGetLocal [uint8] localIndex [v] --> / --> [v] Sets or retrieves variable offset from frame base pointer
OpClosure [uint16] const, [uint8] free [free...] --> [closure] Creates closure wrapping compiled fn and free cells
OpCall [uint8] numArgs [fn, args...] --> [frame] Allocates new Frame on call stack, transfers execution
OpReturnValue / OpReturn none [frame] --> [returnVal] Restores caller frame and pushes return value
